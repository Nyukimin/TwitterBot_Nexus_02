# ディレクトリ移行計画

## 📋 目的

プロジェクトのディレクトリ構成を整理し、ユーザー毎の設定・データを `config/{username}/` 配下に集約する。

---

## 🎯 移行の目標

1. **ユーザーデータの一元管理**: 各ユーザーの設定・データを独立したディレクトリで管理
2. **保守性の向上**: ユーザー追加・削除が容易になる
3. **データの整理**: 設定ファイル、画像、プロファイルを明確に分離

```python
user_data_dir = f"config/{username}/profile"
```

### **3. 画像保存先**

**対象ファイル:**

**修正内容:**
```python

image_path = f"images/{image_name}"

# 修正後
image_path = f"config/{username}/images/{image_name}"
```

### **4. YAML設定ファイルの読み込み**

**対象ファイル:**
- `reply_bot/config.py`

**修正内容:**
```python
# 修正前
def load_config(config_file="config/accounts.yaml"):
    with open(config_file, 'r', encoding='utf-8') as f:
        return yaml.safe_load(f)

# 修正後
def load_config(username=None):
    if username:
        config_file = f"config/{username}/accounts.yaml"
    else:
        # デフォルト設定を読み込む
        config_file = "config/default/accounts.yaml"
    
    with open(config_file, 'r', encoding='utf-8') as f:
        return yaml.safe_load(f)
```

## 🔙 ロールバック手順

移行に問題が発生した場合、以下の手順でロールバック可能：

```bash
# バックアップから復元
rm -rf TwitterBot_Nexus_02
cp -r TwitterBot_Nexus_02_backup_YYYYMMDD TwitterBot_Nexus_02

# または、Gitでロールバック
git reset --hard HEAD~1
```

## ⚠️ 注意事項

1. **バックアップの必須**: 移行前に必ずバックアップを取る
2. **テストの実施**: 各ユーザーで動作確認を行う
3. **段階的な移行**: 一度に全ユーザーを移行せず、1ユーザーずつテスト
4. **コミット頻度**: 各Phaseごとにコミットして、ロールバック可能にする
5. **ドキュメント更新**: 移行後、INSTALL.mdやREADME.mdを更新
